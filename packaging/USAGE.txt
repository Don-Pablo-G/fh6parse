fh6parse 1.4.1 — CNC tool list / min-Z report

Windows:  double-click fh6parse.exe  (or run from Command Prompt)
Linux:    ./fh6parse                 (or fh6parse --gui)

GUI
  fh6parse.exe
  fh6parse.exe --gui
  python3 -m fh6parse --gui   (Linux/Windows git checkout; same yellow UPDATE bar)

Reports next to the NC file (A4 + 80 mm text and HTML)
  fh6parse.exe C:\path\program.nc
  ./fh6parse /path/program.nc
  fh6parse.exe program.nc --machine vf-4ss
  fh6parse.exe program.nc --format 80mm-load
  fh6parse.exe program.nc --format 80mm-set
  (--format 80mm or 80mm-run = RUN; 80mm-min still means LOAD)

Output folder
  fh6parse.exe program.nc -o D:\reports

Header comments like (N10 - OP1) / (N20 - OP2) get a separate tool list each,
as if you changed M97 P# in main. Each list follows M97/M99 until M30.
Tool change: Txx M6 on one line, or T then M6 (common CAM split). A T without
M6 is only a carousel preselect until M6. Tool description: comment on the
T / M6 line, or the line above, plus the line immediately below. T#n / H#n /
D#n use the #n= value (and the comment on that assign, e.g. #100=1 (Frez fi12)
then T#100 prints T1 (#100)). H# / D# must use the same # as T# or a literal
that equals that tool; otherwise WARNING.
M00 / M0 is listed in EACH TOOL CHANGE (not the tool list) with comments above,
on, and below that line when they exist. M01 is not listed.
G54–G59 belong in the file preamble only (before the first Txx M6 or M97/M98).
A later work offset prints WARNING: G55 after operation started (L…).
G68 (coordinate rotation) always prints on LOAD / SET / RUN / A4: which T
turned it on and which T cancelled with G69. Missing G69 is
WARNING: G68 T… L… without G69 — cancel before M30. 2D G17 G68 X Y R rotates
the work envelope; G68.2 / 3D is warned but not transformed.
If the mill has max_rpm, a tool S above that prints WARNING: S… exceeds mill max ….
Comments containing ! are listed as programmer notes.
G95 (feed per rev) still on at the next T or M30 prints a WARNING to set G94.
A Txx M6 that never moves warns (empty pocket), except the last tool change —
that is spindle prep for the next cycle. Rapids-only tools (probe / G65-style)
warn that there is no feed.
G65 P9810 / P9811… (Haas/Renishaw, not in the file): XY at rapid, Z at F,
Min Z at the probe depth. G65 P9832/P9833 is probe on/off (no move).
G65 P to an O-number in the same file sets #1–#26 from A–Z (Fanuc locals)
and runs that sub until M99 (L repeats).
Approx machine time and Min Z follow the programmed path: GOTO / IF GOTO,
WHILE/DO/END, M97/M98 L repeats, G65, and canned-cycle L (G91 steps XY between
holes; G90 repeats the same XY). Skipped tools show Min Z n/a. Time is summed
from G0/G1/G2/G3, F#nnn, and Haas/Fanuc canned cycles (G73 chip-break 0.2 mm,
G83 full retract to R, G84 retract at 1.0×F).
Rapids and tool-change time come from the mill in fh6parse-kiosk.ini
([machine.<id>] plus kiosk.machine). Built-in default is 20 m/min and 0 s
tool change. Optional per mill: ATC X/Y/Z and work offset X/Y/Z in G53 mm
(B0 C0), plus tool length. Then Txx M6 rapids Z then XY to that mill’s ATC;
work G0 is timed in G53. Empty tables keep the old estimate. Optional travel
X/Y/Z min and max (six fields, G53 mm) prints a labeled rectangle of where
the work offset may sit so programmed work stays inside the envelope; corners,
center, and max Ø (centred outside G41/G42) are on the ticket. No accel.
A trailing + means missing F or S.
Each operation shows Cycle (that path until M30). Factory RUN prints a time split:
G0 / cut / rotary / canned / probe / ATC stacked per T (last programmed F, including
F#n). A4 office default is still the simple share chart; tick **Time split** (or
**Use RUN pack**) on the Windows / Linux GUI. F2 on the kiosk has a LOAD | SET | RUN
tick matrix (same rows as the office checklist). Factory LOAD is T / H / D / S /
Min Z / load boxes / sign-off; SET is mill, STEP, offset, cycle, ! notes; RUN is
the full slip without load boxes or sign-off. G68, D vs T, empty pocket, S max,
late offset, G95, and travel-too-big always print. Extra warnings are a separate
tick (on for factory RUN). Text/80 mm share bars use a solid block (CP852); the
RUN split uses G/F/R/C/P/A letters. A4 HTML uses a CSS track (stacked when time
split is on).

Print: open the GUI, load the NC file, tick report sections next to the
preview, then Print A4 or Print 80 mm (paper size only — same ticks).
  A4:     A4 paper, 100%, headers/footers off
  80 mm:  thermal printer, 80 mm paper, 100%, do not fit to A4
  STEP views: click STEP folders… and pick the company .stp/.step share
  (several folders allowed; saved in fh6parse-kiosk.ini next to the exe).
  A wireframe 3D cube appears when the stacked isometrics are ready. The
  chip next to it (kiosk) / status extra (GUI) says why a cube is missing:
  searching…, rendering…, no STEP, Z: off (company share down), or no CAD. The same
  stacked views appear above the report preview (GUI) and under the highlight
  (kiosk) so a wrong STEP can be caught before print. Print never
  waits — if the model is missing the report is text only.
  Language: Polski / English radios (top right). Default English. Saved in the
  same fh6parse-kiosk.ini as STEP folders (and in %USERPROFILE%\.config\fh6parse\ui.ini).
  Last NC folder, report output folder, A4 vs 80 mm preview, and the
  report section checklist are stored there too.
  If CAM overwrites an open .nc (same path, new mtime or size), the
  preview reloads from disk. Wait until Reading… / Reloaded … before print.
  Machine: combo on the preview row. Add mill… writes a [machine.<id>]
  section to %USERPROFILE%\.config\fh6parse\machines.ini (rapids, B/C rapid,
  tool-change seconds, optional max rpm, optional G53 ATC X/Y/Z, work offset
  X/Y/Z, travel min/max per axis) so UPDATE cannot replace the mill list.
  The kiosk has the same form in settings (F2). You can still add
  [machine.<id>] by hand in that file or in ui.ini. Current mill is
  kiosk.machine in the same files.
  Views are visible edges only (no shading). The longest axis is across the
  80 mm width; height is cropped to the part (a long shaft is a thin strip).
  Update: if origin (git GUI) or GitHub Releases (frozen exe) has a newer
  build, a yellow UPDATE to x.y.z bar appears under the mill/print row
  (same single-button flow as the kiosk). One click installs and restarts.
  Never automatic. The check also runs when you click back into the window.
  Frozen exe: bump version, git tag vX.Y.Z, push the
  tag — GitHub Actions builds and attaches fh6parse-X.Y.Z+sha-windows-x64.exe
  (and fh6parse-X.Y.Z-windows-x64.exe so older UPDATE still finds it).
  Local fallback: packaging\build_windows.bat then packaging\publish_windows.ps1
  (needs gh). Keep the ini next to the exe.

Raspberry Pi 5 kiosk (Waveshare 13857 portrait 600x1024) — version 1.4.1
  Full wiring + OS + printer + update: packaging/LINUX-KIOSK.md
  Pi 5 hardware poster (pins + wires): packaging/LINUX-KIOSK-WIRING.pdf
  Hardware archive (SKU/EAN if shops die): packaging/HARDWARE.md
  GPIO adapter: screw terminal on the 40-pin header (Kamami 588019), or on a GPIO riser if the cooler fights it.
  Storage: Pimoroni NVMe Base Duo (PIM704) under the Pi (Botland 24851).
  Disk: official Raspberry Pi 512 GB 2230 from SSD Kit RPI-25484 (disk only; not the kit HAT+).
  Cooler: official Raspberry Pi Active Cooler (Botland RPI-23925) on the FAN header.
  Stick port: metal USB 3.0 Type-A 27 mm panel socket (Allegro 17741983408) to a Pi USB 3 port.
  Case: PETG, vents above cooler and below Duo. Clamp USB-C and HDMI0; no USB-C extension.
  Must-do / shop notes: packaging/HARDWARE.md and LINUX-KIOSK.md §2.13.
  Harness: 24 AWG GPIO, 22 AWG 3.3 V / 5 V / GND, Faston on vandals.
  Operator sheet (Polish): packaging/LINUX-KIOSK-PL.md
  64-bit Raspberry Pi OS Desktop. raspi-config: X11 + desktop autologin.
  Official 27 W USB-C PSU. micro-HDMI on HDMI0. Same BCM pins as Pi 3/4.
  sudo apt install python3-gpiozero python3-lgpio python3-rpi-lgpio python3-tk git
  Do not install python3-rpi.gpio (Pi 5 RP1 GPIO needs lgpio).
  git clone https://github.com/Don-Pablo-G/fh6parse.git
  cd fh6parse && sudo pip3 install -e . --break-system-packages
  python3 -m fh6parse --version          (expect fh6parse 1.4.1+<git sha>)
  python3 -m fh6parse --kiosk --config /etc/fh6parse-kiosk.ini
  Copy packaging/fh6parse-kiosk.ini.example to /etc/fh6parse-kiosk.ini
  Autostart: packaging/fh6parse-kiosk.service
  Once, so UPDATE can restart the unit:
    echo 'kiosk ALL=(root) NOPASSWD: /usr/bin/systemctl restart fh6parse-kiosk' | sudo tee /etc/sudoers.d/fh6parse-kiosk
    sudo chmod 440 /etc/sudoers.d/fh6parse-kiosk

    Need 1.4.1. Later 1.4.1 git commits (preview, mill table, Add mill, travel /
    offset box, on-screen isometric, empty-pocket) still keep that number — UPDATE then shows a hash.
    If --version is older than 1.4.1, SSH:
      cd /home/kiosk/fh6parse && git pull --ff-only && sudo systemctl restart fh6parse-kiosk
    From 1.3.2: on start the kiosk fetches origin in the background, and
    again after the screensaver wakes. If a newer commit exists, a yellow
    UPDATE to x.y.z button appears (touch or U).
    It does not update until you tap it; one tap pulls and restarts the kiosk.
    Print still works offline. Screen shows v1.4.1+<sha> at the top.
    CLI:
      python3 -m fh6parse --version
      python3 -m fh6parse --update
      python3 -m fh6parse --version
    Pulls with --ff-only, skips pip unless pyproject.toml changed, restarts
    fh6parse-kiosk (tries sudo -n if needed). Does not change
    /etc/fh6parse-kiosk.ini.
    After a pyproject change, pip reinstalls '.[models]' when CAD is already
    installed so STEP cubes survive. A kiosk that never had CAD stays -e .
    If cubes vanish, re-run pip install -e '.[models]'.
    One-file ARM tarball cannot --update and shows no button; copy a new
    tarball or switch to git (LINUX-KIOSK.md §3.2 / §8.4).
    Badge only v1.4.1 (no +sha) and no UPDATE: running code cannot see .git

  Keyboard/mouse (troubleshooting, hot-plug OK): arrows, click, wheel, F, M, S, U.
  F2 or C (or click PL/EN) opens settings: Polish default, mill, Add mill…,
  LOAD / SET / RUN content ticks, GPIO pins (file A/B, mill A/B, RUN / LOAD /
  SET, optional sleep/wake), Reverse on each knob, ticks per tooth, print wait after a
  ticket (button_delay, default 2 s). Language, GPIO, and the three report
  packs are saved in ~/.config/fh6parse/ui.ini (survives UPDATE). Mills are
  saved in ~/.config/fh6parse/machines.ini (also survives UPDATE; never
  written into the git clone).
  Escape closes the mill form first, then settings, then leaves fullscreen.

  File encoder (DFRobot EC11 A/B) highlights a file (last wraps to first).
  Mill encoder cycles mills in the mill list under the files (name also
  under the title; last wraps to first). Reverse in settings /
  encoder_swap / encoder_mill_swap if the list moves the wrong way. The
  band under the mills shows each operation (tool count, cycle time, 3D
  ready) and the isometric when ready so you can see OP1 vs OP2 before
  print. Files, mills, preview, and print chips are stacked for 600x1024
  (panel stood on the short edge). Windows / Linux GUI layout is unchanged.
  Three vandal buttons sit under the screen; colour chips on the bottom of
  the UI match left→right: green LOAD (short / M), yellow SET (setter / S),
  red RUN (full / F). 16 mm 5-pin: C to GND, NO to GPIO, NC unused; LED +
  to 5 V, LED − to GND (rings always on). Spare GPIO (BCM 25) is optional
  sleep/wake: press to blank, press again to wake. Leave it unwired — the
  pin sits on the pull-up and never fires; idle timeout, knobs, USB, and
  HID still work. After a ticket, LOAD / SET / RUN wait button_delay seconds
  (default 2) so a second press does not print two slips.
  The kiosk asks the P047 (DLE EOT) before RUN / LOAD / SET. Cover open, no paper,
  or a jam stays on the status line and does not cut a blank slip. No reply
  still prints (same as before). Windows GUI print is the browser, not lp0.
  After 60 seconds idle the screen goes black. Rotary encoder, USB insert,
  keyboard, mouse, or the optional spare GPIO wakes it. Spare while awake
  blanks the panel. GPIO print buttons while asleep are ignored. Pi 5 J2
  (PWR_BTN) is an optional hardware power switch, not a GPIO; omit it and
  USB-C still boots as usual. See LINUX-KIOSK.md §2.7 / §2.8.
  With a stick inserted the count line shows Safe to remove (Można wyjąć)
  when idle, or Reading USB — wait while preview/STEP copy runs. Overwriting
  the highlighted .nc on the stick reloads preview (mtime and size).

STEP models on the 80 mm ticket (kiosk, optional)
  Put a matching .stp / .step on the USB stick (next to the .nc or in a
  subfolder). Company model_roots are a fallback if the stick has none.
  That folder is read-only: fh6parse never writes or deletes files there
  (bitmaps go to /tmp/fh6parse-models). Pi: packaging/connect-windows-share.sh
  maps the office Z: UNC (net use Z: on Windows) to /mnt/fh6parse-cad, CIFS
  ro, automount when Ethernet is plugged. Windows GUI: STEP folders… —
  prefer \\server\share so the letter need not stay Z:.
  pip install -e '.[models]'   (git checkout; not in the one-file Pi tarball)
  No cube: kiosk chip searching… / rendering… / no STEP / Z: off / no CAD (print anyway).
  Matching starts at the NC name prefix. G-code rev must match the .stp rev.
  If the NC has no rev, the latest matching .stp is used (USB copy wins).
  Two opposite isometric line drawings, stacked, cropped to the part, at the top of
  SET and RUN tickets. LOAD never prints STEP / offset images. The same drawing appears on the GUI preview and under the
  kiosk highlight when ready. A wireframe 3D cube appears when the bitmap is ready.
  Missing or still-rendering models never block print.
