fh6parse 1.4.0 — CNC tool list / min-Z report

Windows:  double-click fh6parse.exe  (or run from Command Prompt)
Linux:    ./fh6parse                 (or fh6parse --gui)

GUI
  fh6parse.exe
  fh6parse.exe --gui

Reports next to the NC file (A4 + 80 mm text and HTML)
  fh6parse.exe C:\path\program.nc
  ./fh6parse /path/program.nc
  fh6parse.exe program.nc --machine vf-4ss

Output folder
  fh6parse.exe program.nc -o D:\reports

Header comments like (N10 - OP1) / (N20 - OP2) get a separate tool list each,
as if you changed M97 P# in main. Each list follows M97/M99 until M30.
Tool description: comment on the Txx M6 line, or the line above, plus the
line immediately below. Comments containing ! are listed as programmer notes.
G95 (feed per rev) still on at the next T or M30 prints a WARNING to set G94.
Approx machine time is summed from G0/G1/G2/G3, F#nnn, and Haas/Fanuc canned
cycles (G73 chip-break 0.2 mm, G83 full retract to R, G84 retract at 1.0×F).
Rapids and tool-change time come from the mill in fh6parse-kiosk.ini
([machine.<id>] plus kiosk.machine). Built-in default is 20 m/min and 0 s
tool change. No accel. A trailing + means missing F or S.
Each operation shows Cycle (that path until M30) and a share chart of each T.
FULL also prints % of cycle on each Txx M6. MIN adds H/D/S to load and
H/D/G95 mismatch flags on that short slip. Text/80 mm uses a solid block bar
(CP852); A4 HTML uses a black CSS track.

Print: open the GUI, load the NC file, Print A4 or Print 80 mm.
  A4:     A4 paper, 100%, headers/footers off
  80 mm:  thermal printer, 80 mm paper, 100%, do not fit to A4
  STEP views: click STEP folders… and pick the company .stp/.step share
  (several folders allowed; saved in fh6parse-kiosk.ini next to the exe).
  A wireframe 3D cube appears when the stacked isometrics are ready. Print never
  waits — if the model is missing the report is text only.
  Language: Polski / English radios (top right). Default English. Saved in the
  same fh6parse-kiosk.ini as STEP folders (and in %USERPROFILE%\.config\fh6parse\ui.ini).
  Machine: combo on the preview row. Add [machine.<id>] sections in the ini
  (rapid_mm_min, tool_change_s). Current mill is kiosk.machine in the same files.
  Views are visible edges only (no shading). The longest axis is across the
  80 mm width; height is cropped to the part (a long shaft is a thin strip).
  Update: if origin (git GUI) or GitHub Releases (frozen exe) has a newer
  build, a yellow UPDATE button appears after launch. One click installs and
  restarts. Never automatic. Frozen exe: packaging\build_windows.bat then
  packaging\publish_windows.ps1 (needs gh). Keep the ini next to the exe.

Raspberry Pi 5 kiosk (portrait 600x800) — version 1.4.0
  Full wiring + OS + printer + update: packaging/LINUX-KIOSK.md
  64-bit Raspberry Pi OS Desktop. raspi-config: X11 + desktop autologin.
  Official 27 W USB-C PSU. micro-HDMI on HDMI0. Same BCM pins as Pi 3/4.
  sudo apt install python3-gpiozero python3-lgpio python3-rpi-lgpio python3-tk git
  Do not install python3-rpi.gpio (Pi 5 RP1 GPIO needs lgpio).
  git clone https://github.com/Don-Pablo-G/fh6parse.git
  cd fh6parse && sudo pip3 install -e . --break-system-packages
  python3 -m fh6parse --version          (expect fh6parse 1.4.0)
  python3 -m fh6parse --kiosk --config /etc/fh6parse-kiosk.ini
  Copy packaging/fh6parse-kiosk.ini.example to /etc/fh6parse-kiosk.ini
  Autostart: packaging/fh6parse-kiosk.service
  Once, so UPDATE can restart the unit:
    echo 'kiosk ALL=(root) NOPASSWD: /usr/bin/systemctl restart fh6parse-kiosk' | sudo tee /etc/sudoers.d/fh6parse-kiosk
    sudo chmod 440 /etc/sudoers.d/fh6parse-kiosk

  Update (git checkout only; never automatic)
    Need 1.4.0. If --version is older, SSH:
      cd /home/kiosk/fh6parse && git pull --ff-only && sudo systemctl restart fh6parse-kiosk
    From 1.3.2: on start the kiosk fetches origin in the background.
    If a newer commit exists, a yellow UPDATE to x.y.z button appears (touch or U).
    It does not update until you tap it; one tap pulls and restarts the kiosk.
    Print still works offline. Screen shows v1.4.0 at the top.
    CLI:
      python3 -m fh6parse --version
      python3 -m fh6parse --update
      python3 -m fh6parse --version
    Pulls with --ff-only, skips pip unless pyproject.toml changed, restarts
    fh6parse-kiosk (tries sudo -n if needed). Does not change
    /etc/fh6parse-kiosk.ini.
    After a pyproject change, re-run pip install -e '.[models]' if you use STEP
    views (--update installs the package without that extra).
    One-file ARM tarball cannot --update and shows no button; copy a new
    tarball or switch to git (LINUX-KIOSK.md §3.2 / §8.4).

  Keyboard/mouse (troubleshooting, hot-plug OK): arrows, click, wheel, F, M, U.
  F2 or C (or click PL/EN) opens settings: Polish default, switch to English.
  Language is saved in ~/.config/fh6parse/ui.ini (survives UPDATE).
  Escape closes settings first, then leaves fullscreen, then closes.

  Encoder highlights a file. FULL prints the current 80 mm ticket; MIN prints
  the short ticket (T, H/D/S to load, description, min Z, mismatch flags).
  After 60 seconds idle the screen goes black. Rotary encoder, USB insert,
  keyboard, or mouse wakes it. GPIO print buttons while asleep are ignored.

STEP models on the 80 mm ticket (kiosk, optional)
  Put a matching .stp / .step on the USB stick (next to the .nc or in a
  subfolder). Company model_roots are a fallback if the stick has none.
  pip install -e '.[models]'   (git checkout; not in the one-file Pi tarball)
  Matching starts at the NC name prefix. G-code rev must match the .stp rev.
  If the NC has no rev, the latest matching .stp is used (USB copy wins).
  Two opposite isometric line drawings, stacked, cropped to the part, at the top of
  FULL and MIN tickets. A wireframe 3D cube appears when the bitmap is ready.
  Missing or still-rendering models never block print.
  Full matching table and NAS mount: packaging/LINUX-KIOSK.md §3.7
